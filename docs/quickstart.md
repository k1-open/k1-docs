# K1 快速开始

K1 开发资料可以先下载、评估和开发，不需要先购买硬件。硬件只在进行实物显示、功耗、佩戴、射频、可靠性和整机联调时按需购买。

## 1. 选择开发路径

| 目标 | 建议入口 |
|---|---|
| 开发 Android 应用 | `k1-protocol`、`k1-sdk`、`k1-apps` |
| 开发 BLE 配件或调试工具 | `k1-protocol`、`k1-ble-controller` |
| 做结构适配或打印验证 | `k1-mechanical` |
| 查看电气接口和测试点 | `k1-hardware` |
| 适配 Linux/BSP | `k1-v851s-bsp` 和网盘中的完整 SDK |
| 购买整机或显示模组 | 邮件或电话联系 K1 项目团队 |

## 2. 获取资料

1. 先从 GitHub 阅读协议、示例和说明。
2. 大体积 SDK、工具链和封版资料从 [百度网盘](https://pan.baidu.com/s/1eL-c3V66wPL7c91cLX-_5A?pwd=33pb) 下载，提取码 `33pb`。
3. 解压到独立目录，不要覆盖本机已有 SDK。
4. 记录下载日期、关键文件版本和对应 GitHub commit。

## 3. 无硬件阶段

- 阅读 BLE GATT 和 Display/Audio/OTA 协议。
- 运行 Python 协议参考实现，生成并校验测试帧。
- 使用 LVGL 素材和 App 示例验证界面、导航和数据流。
- 使用 STEP 文件检查结构适配和打印可行性。

## 4. 硬件联调阶段

- 准备 K1 官方硬件、对应版本刷机包和 USB 线。
- 按 [刷机与恢复](flashing.md) 操作。
- 先读取设备信息、协议版本和电量，再验证显示、音频、传感器、BLE 和 OTA。
- 连接问题先看 `k1-hardware/SUPPORT.md` 中的信息清单。

## 5. 安全边界

- 不要向公开仓库提交真实密钥、证书、客户数据或生产校准参数。
- 不要在量产固件中使用示例 App 中的客户端 API Key。
- 不要尝试绕过显示封版、固件签名或设备认证。
- 不要把开发资料用于 PCB 制造、贴片生产或批量复制。
