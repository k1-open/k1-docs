# K1 刷机与恢复

刷机资料和工具适用于 K1 官方硬件或经 K1 项目团队确认的样机。不同硬件版本、存储配置和固件包不可混用。

## 1. 所需资料

- 对应硬件版本的 K1 固件镜像
- [主板下载说明](https://github.com/k1-open/k1-v851s-bsp/blob/main/docs/guides/主板下载说明.docx)
- [K1 OTA 升级操作说明](https://github.com/k1-open/k1-v851s-bsp/blob/main/docs/guides/K1%20OTA升级操作说明.docx)
- [K1 调试说明](https://github.com/k1-open/k1-v851s-bsp/blob/main/docs/guides/K1调试说明.docx)
- PhoenixSuit 和 USB 驱动

GitHub 中的文档链接在本地查看时可能无法跳转到另一个仓库，请按仓库名称打开对应文件。

## 2. 刷机前检查

1. 确认设备型号和硬件版本。
2. 核对固件文件名、日期和 SHA-256。
3. 备份设备内需要保留的数据。
4. 保持 USB 连接稳定，不使用无供电的扩展坞。
5. 确认电量充足，刷机过程中不要断电。

## 3. USB 刷机

1. 安装 Allwinner USB 驱动。
2. 打开 PhoenixSuit。
3. 选择与硬件版本匹配的镜像。
4. 按主板下载说明进入刷机模式。
5. 等待烧录完成，不要中途拔线。
6. 首次启动后检查设备信息、协议版本、显示、音频和 BLE。

具体按钮、短接点、串口参数和工具版本以对应版本的《主板下载说明》和《K1 调试说明》为准。

## 4. OTA 升级

OTA 必须使用同一发布渠道提供的签名包。升级前确认：

- 当前固件版本
- 目标固件版本
- 硬件版本和分区布局
- 电量和网络状态
- 回滚方式

OTA 流程、状态机和错误处理见 `k1-protocol/docs/ota.md`。

## 5. 恢复

刷机失败时：

1. 断开再重新连接 USB。
2. 重新进入下载模式。
3. 使用完整镜像而非单个分区文件恢复。
4. 检查驱动、线材、USB 口和工具日志。
5. 仍无法恢复时，提供设备版本、操作步骤、完整日志和错误截图联系支持。

## 6. 禁止事项

- 不使用来源不明的固件包。
- 不混用不同硬件版本的镜像。
- 不公开签名私钥、设备证书或生产测试参数。
- 不通过修改固件绕过显示封版或安全校验。
