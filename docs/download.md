# K1 资料下载与使用说明

本文说明 K1 资料在 GitHub 和百度网盘之间的分工、完整包的内容边界，以及显示核心封版后的使用方式。

## 1. GitHub 和百度网盘分别做什么

| 渠道 | 用途 |
|---|---|
| GitHub | 源码浏览、协议、SDK、App 示例、Issue、Pull Request、版本和变更记录 |
| 百度网盘 | 完整 K1 开发资料、较大体积的系统源码、工具链、打包资料和辅助文件 |

GitHub 不直接承载完整 24GB 级别的资料包；用户需要时通过百度网盘下载。网盘是外部下载渠道，GitHub 的仓库内容仍是代码和文档的官方版本入口。

## 2. 下载入口

- 提取码：`33pb`
- 分享目录：`k1`

## 3. 完整包的内容边界

网盘中的 `k1` 是完整 K1 资料包，包含开放开发资料及封版后的系统资料。具体文件和版本以分享目录实际内容为准。

显示部分采用封版方式处理：

- 显示驱动及核心实现不提供开放源代码
- 面板初始化、寄存器序列和显示时序不开放
- Gamma、亮度、色温和均匀性校准不开放
- 显示私有固件、生产测试、治具和校准数据不开放
- 显示功能通过官方硬件、显示模组和公开 Display API 提供

封版表示相关实现不会作为开源源代码交付，不代表可以绕过、反编译或复制其中的私有实现。

## 4. 下载和使用步骤

1. 打开百度网盘链接并输入提取码 `33pb`。
2. 下载分享目录 `k1`，不要只下载其中某个不完整的子目录。
3. 解压到独立目录，例如：
   ```text
   E:\K1\k1-download
   ```
4. 先阅读目录中的说明文件，再按 GitHub 对应仓库的 README 进行构建和刷机。
5. 不要覆盖已有的 SDK、工具链或本地配置；升级前先备份。
6. 记录下载日期、分享目录名称和对应 GitHub commit，方便后续排查版本差异。

## 5. 版本与兼容性

下载完整包后，建议记录：

- GitHub 仓库名称和 commit SHA
- 百度网盘分享日期
- 包内版本号或文件日期
- 适用硬件版本
- 适用的 SDK、固件和协议版本

如果包内提供校验文件，请在使用前核对哈希值。没有校验文件时，至少核对文件数量、目录结构和关键文件日期。

## 6. 安全与合规

- 不要将网盘中的密钥、证书、客户数据、生产参数或私有显示实现重新上传到 GitHub。
- 不要把完整包直接上传到公开仓库。
- 不要尝试绕过显示封版、固件签名或设备认证。
- 第三方文件继续遵循其原始许可证；在再分发、生产或商业使用前必须确认授权。
- 购买官方硬件不等于获得 PCB、BOM、贴片、量产或显示模组复制授权。
